# Playbook：新增 / 扩写节点

适用：用户提出新主题、AI 发现知识缺口、收件箱条目需要转为正式节点。

## 步骤

1. **查重**：在 `content/INDEX.md` 中搜索相关关键词（中英文都搜）。
   - 已有相同概念 → 转为「扩写」，不要新建。
   - 有高度重叠的节点 → 考虑合并到已有节点的某一节。
2. **选 kind**（判断标准）：
   - 需要*理解*的概念/规则 → `knowledge`
   - 需要*练习*才能提升的能力 → `skill`
   - 关于*外部世界*（机构、策略原型、监管、职业） → `industry`
   - 可以*去读/去用*的东西（数据、书、论文、工具、社区） → `source`
   - 关于*怎么想*（原则、心智模型、偏差、清单） → `mindset`
3. **新建**：`npm run content:new -- <kind> <id> "标题"`（id 用英文 kebab-case，能望文生义）。
4. **填写 frontmatter**：
   - `summary` 一句话说清「是什么 + 为什么重要」。
   - `domains` 第一个是主领域。
   - `importance`：5=核心必修，4=重要，3=一般，2=了解即可，1=冷门。
   - 时效性内容设置 `review`（一般 +6 个月），正文写「截至 YYYY-MM」。
   - `confidence`：有可靠出处 → high；常识但细节可能有误 → medium；记忆模糊/行业传闻 → low。
5. **写正文**：按 `content/_meta/templates/<kind>.md` 的结构。要求：
   - 面向「个人量化」视角：这对一个资源有限的个人意味着什么？
   - 至少一个「常见误区」或「坑」。
   - 用 `[[id]]` 链接到已有节点。
6. **补关联（双向）**：
   - 本节点 `related`/`prereqs` 指向相关节点。
   - 打开 2-3 个最相关的已有节点，在其 `related` 或正文中加入对新节点的引用。
7. **验证**：`npm run check` 通过。
8. **记录**：在 `CHANGELOG.md` 顶部追加条目。

## 扩写已有节点时

- 保留原有结构和用户写的内容（用户写的段落不要删改，可以在其后补充）。
- 更新 `updated`；若内容涉及时效信息，同时更新 `review`。
- 不要改 `status`/`level` 等用户进度字段。
